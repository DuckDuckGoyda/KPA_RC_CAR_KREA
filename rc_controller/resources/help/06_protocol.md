# Протокол

Программа работает по «Протоколу информационно-логического взаимодействия» v1.0. Всё, что может меняться, задаётся в профиле.

## Формат пакета

```
AC 53 | LEN | SQN | ADDR | CODE PARAM… | CRC        команда (ПК → машинка)
AC 53 | LEN | SQN | ADDR | ACK  DATA…  | CRC        ответ   (машинка → ПК)
```

| Поле | Размер | Значение |
|---|---|---|
| `AC 53` | 2 | синхрослово — начало пакета |
| LEN | 1 | число байт после LEN (SQN … CRC), от 4 до 253 |
| SQN | 1 | номер пакета: 0 в начале сеанса, +1 каждый пакет (и при повторе), по модулю 255 |
| ADDR | 1 | адрес, у всех устройств 1 |
| CODE PARAM | LEN−3 | код команды и параметры |
| ACK | 1 | 0 — принята, 1 — неверный адрес, 2 — ошибка CRC, 3 — недопустимый параметр |
| DATA | LEN−4 | данные ответа (телеметрия, версия) |
| CRC | 1 | контрольная сумма всех байт от LEN до последнего байта данных |

UART: 19200 бод, 8 бит данных, без чётности, 1 стоп-бит. Многобайтовые числа — младший байт первым.

## CRC-8

Полином x⁸+x⁵+x⁴+1 (0x31), вариант **CRC-8/MAXIM-DOW** (Dallas 1-Wire): начальное значение 0x00, биты отражены (в коде — сдвиг вправо с полиномом 0x8C). Контрольное значение для строки `123456789` — **0xA1**. Эталонная реализация на C для прошивки: `docs/protocol/crc8.c`.

Пример: `GET_TEL` с SQN = 0 → `AC 53 04 00 01 04 AB`.

## Обмен

- Инициатор всегда ПК. Следующий запрос уходит только после ответа на предыдущий (или по таймауту).
- Ответ сопоставляется с запросом по **SQN**.
- Нет ответа за `reply_timeout_ms` → повтор (3 раза через 1 с), каждый раз с новым SQN. Команды движения не повторяются — их заменяет более свежая команда.
- Несколько обменов подряд без ответа (`lost_after_failures`) → «Связь потеряна». Макрос при этом прерывается. Первый же ответ восстанавливает связь.
- Ответ с ACK = 2 (машинка получила битый пакет) — команда повторяется.

## Особые случаи в журнале

| Статус | Что значит |
|---|---|
| **эхо** | вернулся ровно тот пакет, что был отправлен, — прошивка работает как эхо. Связь считается живой |
| **опоздал** | ответ пришёл, но уже после таймаута. Стоит увеличить `reply_timeout_ms` |
| **без запроса** | корректный пакет, который не отвечает ни на один запрос |
| **ошибка CRC** | пакет с неверной контрольной суммой; разбор продолжается со следующего синхрослова |
| **таймаут** | ответа не было |

Байты, не похожие на пакет (текст, ответы AT, мусор), показываются как «данные вне пакетов».

## Пока прошивка не отвечает

Если прошивка ещё не умеет отвечать, поставьте в профиле `wait_for_reply = false`: команды будут уходить без ожидания ответа, а связь не будет считаться потерянной.
